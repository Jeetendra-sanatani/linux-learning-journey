🎯 WHAT I LEARNED TODAY

- Linux me har file/directory ka ek owner aur group hota hai.
- Permissions 3 categories ke liye hoti hain:

  Owner  → file ka owner
  Group  → assigned group
  Others → baaki users

- Permission structure:
  [type][owner][group][others]

  Example:
  -rwxr-xr--

  -    → Regular file
  rwx  → Owner
  r-x  → Group
  r--  → Others


🔐 PERMISSION VALUES
  r = Read     = 4
  w = Write    = 2
  x = Execute  = 1
  - = No permission = 0


📊 COMMON PERMISSIONS
  644 = rw-r--r--
  755 = rwxr-xr-x
  700 = rwx------
  600 = rw-------
  777 = rwxrwxrwx  ⚠️ Dangerous

- 777 ka matlab Owner, Group aur Others ke paas
  read + write + execute permissions hain.

- Security assessment me unnecessary world-writable
  files/directories ko investigate karna important hai.


📁 DIRECTORY PERMISSIONS
Files aur directories me permissions ka behavior
thoda different hota hai.

  r = directory contents list karna
  w = files/directories create/delete karna
  x = directory me enter/traverse karna

Important:

  Directory ko practically access karne ke liye
  execute (x) permission important hoti hai.

🔧 PRACTICAL 02 — CHMOD SYMBOLIC MODE
==========================================

Give execute permission to the owner:

Verify again:
$ ls -la scan.sh

==========================================
🔐 SECURITY MINDSET
==========================================

When I see a file during security assessment,
I should not only ask:

  "Does this file exist?"

I should also ask:

  Who owns it?
  Who can read it?
  Who can modify it?
  Who can execute it?
  Is it world-writable?
  Is it executed by a privileged user?
  Can the permission create a security risk?


Important:

  777 ≠ automatically vulnerable

The actual security impact depends on:

  Ownership
  Location
  File purpose
  Execution context
  Privileges
  How the file is used
